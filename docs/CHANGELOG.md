# Changelog

## Unreleased
- M17: Auto-Update. Zentrale und Agents aktualisieren sich im Wartungsfenster pro Server selbst aus ihrem Image-Tag (GHCR), optional OS-Pakete (`apt-get upgrade`) und Neustart bei Bedarf. Neue Images müssen binnen 3 Min gesund sein, sonst läuft wieder der alte Container. Agent: `update.check`, `update.apply` (Zentrale direkt, Agent über einen kurzlebigen Helfer-Container aus dem alten Image), `system.upgrade`, Event `update_result`, Health-Check im Agent-Image. Core: Richtlinien, Tabelle `update_runs`, Zeitplan, Meldungen, `GET /api/updates`, Live-Topic `updates`. Web: Kachel „Auto-Update“ im Serverdetail, Einstellungen → Updates.
- M16: Server im Detail. Verlauf 1 h bis 30 Tage (CPU, RAM, Netz, Temperatur, Disk), größte Ordner (`system.du`), Docker-Belegung (`system.dockerDf`), Aufräumen mit Auswahl, Dienste mit Start/Stopp/Neustart nur über `HZ_AGENT_SERVICES` (`system.services`, `system.service`, fehlgeschlagene Dienste im Inventar und als Meldung), Prozessliste ohne Kommandozeilen (`system.processes`), Herunterfahren mit Step-up (`system.shutdown`).
- Installer `deploy/install.sh`: richtet die Zentrale auf einem frischen Server ein (Docker und Tailscale prüfen oder installieren, `/etc/homelab-zentrale/core.env` mit zufälligem `HZ_SECRET_KEY` in 0600, `HZ_BASE_URL` aus `tailscale status`, Module im Assistenten, Image aus GHCR oder lokal gebaut, Health-Check, `tailscale serve` ohne Funnel, Einmal-Link für den ersten Login). Idempotent, mit `update`, `status`, `uninstall` (`--purge` löscht alles) und `share` für das Share-Gateway. Neue Variable `HZ_INITIAL_MODULES` (gilt nur bis zum ersten Login). Tests mit gestubbtem Docker/Tailscale und ein CI-Job mit echtem Docker. Anleitung in `docs/INSTALL.md`.
- M13: NAS und Speicher (zuerst für ein UGREEN NASync mit UGOS Pro, generisch für jeden Linux-Server). Agent liest md-RAID (`/proc/mdstat`), Volumes mit Geräte-Kette (dm → md → Platte), Platten aus `/sys/block`, NVMe-Temperatur aus hwmon und, mit `HZ_AGENT_SMART=1`, SMART per `smartctl` (`--nocheck=standby`, weckt keine Platte, Cache 10 Min). Override `deploy/docker-compose.agent.smart.yml` (nur Lesezugriff auf die Blockgeräte, `CAP_SYS_RAWIO`), `install-agent.sh --smart`, Einzeiler `… -- <code> --smart`, auf UGREEN-Hardware automatisch. Core: Tabelle `server_storage`, `GET /api/storage[/:id]`, Meldungen für beschädigtes RAID, SMART-Ausfall, defekte Sektoren, Abnutzung und Plattentemperatur mit OK bei Erholung, Modul `storage` (Standard an). Web: Abschnitt „Speicher“ im Serverdetail, Kachel „Speicher“ in der Übersicht. Screenshots in `docs/screenshots/m13/`.
- M12: Gameserver komplett. Schlafmodus (neue Gameserver schlafen nach 15 Min ohne Spieler; der Agent lauscht auf den Spielports und weckt beim ersten Login bzw. Spielpaket, Minecraft-Serverliste zeigt „Schläft“, RAM-Reserve gilt), Zeitpläne für Neustart (mit Warnung an die Spieler) und Backup, Discord-Webhook (online, offline, schläft, aufgeweckt), Spielerstatistik (Spielzeit, Sitzungen, Spitzenzeiten), Mods und Plugins über Modrinth für Paper und Fabric, Backup wiederherstellen per Knopf, Benutzerlink-Rechte „Welt herunterladen“ und „Whitelist-Anfrage“ (Push an den Admin), 7 neue Vorlagen (Satisfactory, Factorio, Enshrouded, Project Zomboid, ARK: Survival Evolved, Rust, V Rising) mit Architektur-Prüfung, Feld „Netz“ am Server für den Hinweis zur Portweiterleitung, Erkennung der Spiel-Container über das Label `homelab.game`, Zeitzone der Vorlagen aus `HZ_TIMEZONE`. Agent: `game.wake.arm/disarm`, `game.mods.list/install/remove`, `game.restore`, Event `game_wake`. Screenshots in `docs/screenshots/m12/`.
- M11: Server anbinden, Gameserver umziehen, Port-Abgleich. „Server hinzufügen“ zeigt einen Code (8 Zeichen, 15 Min, einmalig, nur als HMAC gespeichert) und einen Einzeiler `curl -fsSL https://<zentrale>/install.sh | sudo sh -s -- <code>`; das Skript (vom Core ausgeliefert, ohne Secret) prüft Docker und Tailscale, tauscht den Code (Rate-Limit pro IP und global), schreibt `/etc/homelab-agent/agent.env` (0600) und startet den Agent; die Seite zeigt live „Verbunden“. Gameserver umziehen per Knopf (Step-up): speichern und stoppen, Export (`game.export`, nur `data/`), Übertragung über die Zentrale mit Ack-Fenster, Größenlimit und SHA-256, Import am Ziel mit Prüfung jedes Archiv-Eintrags (`game.import`), Start am Ziel mit neuen Ports; bricht etwas ab, wird das Ziel entfernt und die Quelle wieder gestartet. Port-Abgleich: Soll-Liste offener Ports pro Server (aus dem ersten Inventar), neue öffentliche Ports melden sich als warn mit „Erlauben“. Screenshots in `docs/screenshots/m11/`.
- M10: Prioritäten und automatisches Drosseln. Priorität pro Container und Gameserver (`wichtig`, `normal`, `niedrig`, „darf gestoppt werden“, bei Spielen „auch mit Spielern online“). Zeitpläne pro Stufe (ohne Drosselung oder mit X Kernen, Zeitzone `HZ_TIMEZONE`), RAM-Reserve für `wichtig` (Gameserver starten nur mit Platz, auch nicht per Benutzerlink). Web: Priorität und Drosselung im Container- und Gameserverdetail, Hinweis „gedrosselt“ in den Listen, Automatik im Serverdetail, Kachel „Wer frisst gerade?“ in der Übersicht, „Wieder starten“ bei automatisch gestoppten Containern. Screenshots in `docs/screenshots/m10/`.
